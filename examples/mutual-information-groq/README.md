# Groq mutual-information kernel

This example computes Shannon mutual information in bits from one normalized,
nonnegative `256 x 256` joint-probability matrix:

```text
I(X;Y) = sum_x sum_y p(x,y) log2(p(x,y) / (p(x) p(y)))
```

The zero-probability convention is exact: cells with `p(x,y) == 0` contribute
zero. The implementation deliberately avoids `aten.ones_like`, which the
`groq-r01-groqflow` compatibility snapshot records as rejected. Its nontrivial
operators (`sum.dim_IntList`, `unsqueeze`, `gt.Scalar`, `add.Scalar`,
`where.self`, `log`, `sub.Tensor`, `mul.Tensor`, and `mul.Scalar`) all have
canonical compile evidence in that snapshot. This is preflight evidence only;
the complete graph still needs a Groq compile and hardware execution.

On an allocated Groq node with the GroqFlow environment available, run:

```bash
/home/gbrun/miniconda3/envs/groqflow/bin/python \
  examples/mutual-information-groq/run_groq.py
```

The runner checks a diagonal distribution with expected MI of 8 bits, an
independent uniform distribution with expected MI of 0 bits, and a dense
correlated mixture against an FP64 reference. It then reports the Groq SDK
benchmark latency.

See [RESULTS.md](RESULTS.md) for the live Groq compile, execution, numerical,
and latency evidence recorded on August 31, 2026.

The paper suite uses the matching PolyBench-conformant
[C baseline](../PolyBenchC-4.2.1/scientific/mutual-information/mutual-information.c).
Its `mini` profile uses `N=32` for semantic validation and its `large` profile
reproduces this example's static `N=256` workload; accelerator candidates are
generated by the benchmark rather than copied from this implementation.
